Это пошаговый план на момент официального запуска. Пока идут тесты — ничего
делать не нужно, приложение продолжает работать на текущем (облачном) Supabase.
Когда приложение стабильно и готов к релизу — проходишь этот файл сверху вниз.

## 1. Арендовать сервер (VPS) в РФ

Берём фиксированный VPS (предсказуемая цена, всё в РФ):

- RuVDS: 4 ГБ / 2 ядра / 40 ГБ SSD — ~2 160 руб/мес (хватает на старт)
- Timeweb Cloud: 4 ГБ / 2 ядра — ~3 600 руб/мес
- Selectel — тоже подходит

При заказе выбирай:
- ОС: Ubuntu 22.04 LTS (или 24.04 LTS)
- Диск: минимум 40 ГБ SSD
- Локация: Россия (Москва/СПб)

Запиши IP-адрес сервера, логин (root) и пароль — пришлют на почту.

## 2. Подключиться к серверу

С Windows проще через программу PuTTY или встроенный терминал:

    ssh root@ТВОЙ_IP_АДРЕС

Введёшь пароль — попадёшь в командную строку сервера.

## 3. Установить Docker (один раз)

Docker — это "движок", в котором крутится Supabase. Команды по очереди:

    curl -fsSL https://get.docker.com -o get-docker.sh
    sh get-docker.sh
    docker --version

Если последняя команда показала версию — Docker готов.

---

## 4. Установить самохостинг Supabase

    git clone --depth 1 https://github.com/supabase/supabase
    cd supabase/docker
    cp .env.example .env

Теперь ОБЯЗАТЕЛЬНО поменять пароли и ключи в файле .env (иначе взломают):

    nano .env

Поменяй как минимум эти строки на свои длинные случайные значения:
- POSTGRES_PASSWORD  (пароль базы)
- JWT_SECRET         (длинная случайная строка, 40+ символов)
- ANON_KEY и SERVICE_ROLE_KEY (сгенерируй на https://supabase.com/docs/guides/self-hosting/docker — там генератор из JWT_SECRET)
- DASHBOARD_USERNAME и DASHBOARD_PASSWORD (вход в панель)

Сохранить в nano: Ctrl+O, Enter, потом Ctrl+X.

Запустить:

    docker compose up -d

Проверить, что всё поднялось:

    docker compose ps

Панель управления (Supabase Studio) откроется по адресу http://ТВОЙ_IP:8000
(логин/пароль — те, что задал в DASHBOARD_*).

## 5. Перенести структуру таблиц и логику (без данных)

У тебя уже есть таблицы: shared_jobs, shared_profiles, messages, reviews,
reports, push_tokens (+ логика/политики RLS). Переносим только схему.

1) На СТАРОМ (облачном) Supabase выгрузи только структуру:
   В панели старого проекта — SQL Editor, либо локально:

    pg_dump --schema-only --no-owner "СТРОКА_ПОДКЛЮЧЕНИЯ_СТАРОГО_SUPABASE" > schema.sql

   (строку подключения возьмёшь в старом проекте: Settings -> Database)

2) Загрузи структуру в НОВУЮ базу на сервере:

    docker compose exec -T db psql -U postgres -d postgres < schema.sql

3) Проверь в новой панели (Studio -> Table Editor), что таблицы появились.

Важно: не забудь перенести и политики доступа (RLS policies), функции,
триггеры, и таблицу banned_phones из MODERATION_GUIDE.md — они входят в
schema-only дамп автоматически, если были созданы через SQL.

## 6. Домен и SSL (https)

1) Купи домен (например delnik.ru) у любого РФ-регистратора (reg.ru, timeweb).
2) В настройках домена укажи A-запись на IP сервера.
3) Поставь Caddy или Nginx как обратный прокси с автоматическим SSL
   (Let's Encrypt — бесплатно). Самый простой путь — Caddy:

    # пример Caddyfile
    api.delnik.ru {
        reverse_proxy localhost:8000
    }

   Caddy сам получит и продлит https-сертификат.

После этого адрес API будет https://api.delnik.ru вместо http://IP:8000.

## 9. Переключить приложение и сайт на новый сервер

Когда сервер готов, в приложении меняется ВСЕГО ДВЕ строчки — адрес и ключ:

    // старое (облако):
    Supabase.initialize(url: 'https://ltpcnsoopuvuhfvxokai.supabase.co', anonKey: '...')
    // новое (свой сервер):
    Supabase.initialize(url: 'https://api.delnik.ru', anonKey: 'НОВЫЙ_ANON_KEY')

Это место в коде — файл lib/main.dart (инициализация Supabase).
После правки: flutter pub get -> собрать подписанный APK -> собрать web -> задеплоить.
Пришли мне сигнал "сервер готов, вот новый url и anon key" — я аккуратно внесу
правку в приложение и соберу финальный архив. Секретные ключи (SERVICE_ROLE,
пароль базы) мне НЕ присылай — они живут только на сервере.

## 10. Резервные копии, обновления, догляд

- Бэкап базы (делать регулярно, лучше по расписанию cron):

    docker compose exec -T db pg_dump -U postgres postgres > backup_$(date +%F).sql

  Копию храни не только на сервере (скачивай к себе / во внешнее хранилище).

- Обновление Supabase:

    cd supabase/docker && git pull && docker compose pull && docker compose up -d

- Следи за местом на диске:  df -h
- Логи, если что-то упало:    docker compose logs --tail=100

## 14. Push-уведомления из чата (через RuStore)

FCM (Google) в РФ ненадёжен. У RuStore есть СОБСТВЕННЫЙ сервис push — альтернатива FCM.

- Flutter-пакет: flutter_rustore_push (добавить в pubspec.yaml).
- Условия работы: у пользователя установлен RuStore, он авторизован, разрешён фон.
- Схема:
  1) Приложение получает push-токен от RuStore.
  2) Сохраняем токен в таблицу push_tokens (она у тебя уже есть).
  3) При новом сообщении в чате сервер шлёт push через RuStore API на этот токен.
- Настройка: project_id из RuStore Console → в AndroidManifest.xml, инициализация SDK, обработка входящих.
- Сейчас в приложении только ЛОКАЛЬНЫЕ уведомления (работают, когда приложение открыто).
  Удалённые push (когда приложение закрыто) — это как раз RuStore Push, подключаем на релизе.
- Примечание: если у пользователя НЕТ RuStore (чистый Android/сайт) — push через RuStore не придёт.
  На старте (Android + RuStore) этого достаточно; для сайта можно позже добавить web-push.

Когда дойдёшь до этого шага — пришли сигнал, я подключу flutter_rustore_push и серверную отправку.

## 15. Защита от фейковых регистраций (вход email + код)

Ты прав: email+код проще заспамить одноразовыми почтами. Но это решается,
отказываться от email не нужно:

- Блокировать домены одноразовых почт (готовые списки temp-mail сервисов).
- Rate limit: не больше N кодов с одного IP/устройства в час.
- Обязательное подтверждение почты (код) + лимит аккаунтов на устройство.
- Капча при подозрительной активности.
- Бан по устройству/почте (у тебя уже есть blockUser и banned_phones — добавим banned_emails аналогично).

Сравнение:
- email+код: дёшево (0 ₽), но нужны анти-фрод меры.
- SMS+код: дороже (2.5-4 ₽), но фейков меньше (номер сложнее получить массово).

Рекомендация: старт на email + базовый анти-фрод; при росте спама — добавить капчу или SMS для подозрительных.
