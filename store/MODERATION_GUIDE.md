# Модерация: жалобы, споры и бан по номеру телефона

Это памятка по безопасной модерации «Дельника» на бэкенде Supabase.
Всё делается ТОЛЬКО тобой через панель Supabase (service_role), обычные
пользователи и мошенники к этому доступа не имеют.

---

## 1. Как отслеживать жалобы и спорные ситуации

В приложении уже есть кнопки «Пожаловаться» — они пишут строки в таблицу
`reports`. Смотреть их так:

1. Зайди в Supabase → проект `ltpcnsoopuvuhfvxokai`.
2. **Table Editor → reports** — увидишь все жалобы (кто, на кого/на что,
   причина, дата). Сортируй по `created_at` (сверху свежие).
3. Либо в **SQL Editor** выполни:

```sql
select created_at, reporter_id, target_id, target_type, reason, details
from reports
order by created_at desc
limit 100;
```

Совет: включи в Supabase уведомления на email (Database → Webhooks или
бесплатный внешний сервис), чтобы новые строки в `reports` приходили тебе
на почту. Тогда не придётся заходить вручную.

## 2. Бан по номеру телефона — безопасно (только ты)

Идея: отдельная таблица `banned_phones`. Записывать в неё может ТОЛЬКО
`service_role` (то есть ты из панели Supabase). Обычные пользователи —
не могут читать и не могут писать. Значит:
- мошенники не смогут забанить честных людей (нет прав на запись);
- никто, кроме тебя, список даже не увидит.

### Шаг 1. Создать таблицу и включить защиту (RLS)

Supabase → **SQL Editor** → вставь и выполни:

```sql
-- Таблица забаненных номеров
create table if not exists public.banned_phones (
  phone text primary key,            -- в формате +79991234567
  reason text,
  created_at timestamptz not null default now()
);

-- Включаем построчную защиту
alter table public.banned_phones enable row level security;

-- НЕ создаём ни одной policy для anon/authenticated.
-- Без policy обычные пользователи не могут ни читать, ни писать.
-- service_role (ты в панели) обходит RLS и имеет полный доступ.
```

### Шаг 2. Как забанить номер (делаешь ты в панели)

```sql
insert into public.banned_phones (phone, reason)
values ('+79991234567', 'мошенничество / жалобы');
```

Разбанить:

```sql
delete from public.banned_phones where phone = '+79991234567';
```

### Шаг 3. Не пускать забаненных в приложение

Надёжнее всего проверять на входе через серверную функцию Supabase
(Auth Hook / Edge Function), потому что клиент можно обойти. Простой
вариант — «Before user created / sign-in» hook, который отклоняет вход,
если номер есть в `banned_phones`.

Если пока хочешь только клиентскую проверку (менее надёжно, но быстро),
добавь в приложение после успешного входа запрос через service-функцию —
не используй прямой доступ к таблице с anon-ключом, иначе бан можно
обойти. Скажи мне, когда захочешь это включить, — напишу Edge Function.

> Важно: не давай anon/authenticated никаких policy на `banned_phones`.
> Именно отсутствие policy = никто, кроме тебя, туда не залезет.

## 3. Личный бан пользователя (уже есть в приложении)

Кнопка «Заблокировать» у пользователя (`blockUser`) — это ЛИЧНЫЙ бан:
скрывает контакт только у того, кто заблокировал. Это правильно и
безопасно: один пользователь не влияет на других. Глобальный бан по
номеру (раздел 2) остаётся только за тобой.
