## 1. Контекст и железные правила

«Дельник» — сервис подработки в Калининграде. Flutter (mobile + web) + Supabase.
Сайт написал друг заказчика; заказчик (Антон) полностью переделывает фронтенд.

1. **Бэкенд не трогать.** Supabase/SQL/ключи — только чтение.
2. **`main` не трогать.** Вся работа в `redesign/ui-v2`.
3. **Новый UI за флагом** (`lib/ui_v2/ui_v2_flag.dart`), чтобы старый сайт продолжал работать.
4. **Публикует агент, не человек.** Заказчик дважды заливал файлы руками — оба раза битый результат.
5. **Референс — Авито** (главный) + характер Кворка. Не «перекрасить», а повторить плотность и логику.

### Правила работы (требования заказчика, цитаты)

- «Сначала получил лог, по нему понял, что не так, и только решил ошибку. Не наугад.» → каждой гипотезе предшествует замер.
- «Почему я должен что-то заливать?» → агент коммитит сам и сам проверяет.
- «чето ты завис» → перед долгим действием писать короткую фразу, что делаешь.
- «Читай скиллы не по диагонали».
- «Поспрашивай вопросы и тогда уже начнём» → короткие вопросы с вариантами ответа. Ответ «Фиксируем» = решено.
- Никогда не показывать непроверенную страницу. Сначала проверка — потом ссылка.
- Язык общения — русский, коротко и по делу.

## 5. Сборка прототипа

Прототип генерится Python-билдерами в песочнице агента (`/data/delnik/v2/`), потому что прямая запись большого HTML обрезается:

| Файл | Роль |
|---|---|
| `shared.py` | `CSS` (токены и компоненты) + `SPRITE` (иконки) |
| `build_main.py` | лента, шапка, футер, экран состояний, `ic()` |
| `build_flow.py` | карточка заявки, отклик, публикация |
| `build_account.py` | кабинет, чат, профиль |
| `build_app.py` | **собирает единый `app.html`** |
| `patch_v1.py`, `patch_v2.py` | правки после Visual QA |

```bash
cd /data/delnik/v2
python3 build_main.py && python3 build_flow.py && python3 build_account.py
python3 build_app.py            # -> app.html (≈116 КБ)
python3 /data/skills/artifact-design/scripts/capture_html.py app.html --width 1440
```

В `build_app.py`: `CATS` (9 категорий), `VIEWS` (9 экранов), `JOBS` (16 заявок), `strip_shell()`, `LINKMAP`/`relink()`, JS `route()/paintFeed()/render()`.

## 6. ПУБЛИКАЦИЯ — обязательная процедура

**Главный урок проекта.** У песочницы нет внешней сети, поэтому файл переносится текстом через вызов инструмента. **При переносе большого base64 один символ искажается при той же длине** → gzip ломается → браузер пишет `Failed to fetch`.
Доказано замером: размер совпал (29009 б), git-хеш — нет (`bc03b9b4…` против `aae2fab3…`).

### Схема «9 проверяемых частей»

```bash
# 1) сжать
gzip -9 -n -c /data/delnik/v2/app.html | base64 -w 100 > /tmp/pl.b64
gzip -9 -n -c /data/delnik/v2/app.html | sha256sum    # эталон
```

```python
# 2) нарезать по 30 строк + посчитать git-хеши
import hashlib
lines = [l for l in open('/tmp/pl.b64').read().split('\n') if l]
for i in range(0, len(lines), 30):
    body = ('(self.P=self.P||[]).push("' + ''.join(lines[i:i+30]) + '")\n').encode()
    open(f'/tmp/p{i//30}.js','wb').write(body)
    print(i//30, len(body), hashlib.sha1(b'blob %d\x00' % len(body) + body).hexdigest())
```

3) `cat /tmp/pN.js` по 5–6 штук → залить все сразу через `push_files` (не `create_or_update_file` — требует актуальный SHA и падает).
4) **Обязательно:** `get_file_contents({path:"web/v2/"})` → сверить blob-SHA каждой части с эталоном. Не совпало — перезалить только её.
5) Ждать ~165 с и проверить живую страницу через веб-загрузку (`fast_mode:false`) — краулер исполняет JS и поддерживает `DecompressionStream`.

### Самодиагностика страницы

| Текст на экране | Значение |
|---|---|
| `Загружено частей: N из 9` | часть не выложилась / 404 |
| `Данные повреждены: n б, sha …` | байты искажены; эталон `b97a7b256fc2eac6…`, n = 20079 |
| `Браузер не поддерживает…` | нет `DecompressionStream` |
| `Failed to fetch` | старая версия из кеша → Ctrl+F5 |

### Контрольные суммы текущей сборки

- `app.html`: 104 775 симв. / 116 139 б, sha256 `d51042dd40e1dd17c8cd2d41c27b2413fad4c2c8c73a1be1f005998053748c95`
- gzip -9 -n: 20 079 б, sha256 `b97a7b256fc2eac6fbc9d4aacd0178a96b77a8271a27b5f657111f7e1ffdd990`
- части: `p0 73917b0e` `p1 fc30e73c` `p2 d3964f60` `p3 2fa49a0e` `p4 7d6d753c` `p5 8b6bf8bf` `p6 913950c8` `p7 3cae3e45` `p8 bdaa2633`

## 7. Ограничения среды и разобранные ошибки

| Ограничение | Следствие |
|---|---|
| у PAT нет scope `workflow` → 403 | `.github/workflows/**` не менять; всё для Pages класть в `web/` |
| нет внешней сети (`curl` → 000) | живой сайт проверять только веб-загрузкой |
| `/tmp` не переживает вызовов | временные файлы пересоздавать в том же вызове |
| `npm install` падает (124) | CLI-скиллы не ставятся; читать их исходники через `get_file_contents` |
| в GitHub MCP нет Actions-тулов | статус деплоя — только по живой странице |

Уже починено:
- `Failed to compile application for the Web` — Android-only импорты (`41b002b1`).
- `The library directive must appear before all other directives` — `library;` после `import` (`cc038e5d`).
- `Type 'VoidCallback' not found` — нет `import 'package:flutter/material.dart'`.
- `Branch "redesign/ui-v2" is not allowed to deploy to github-pages` — ветка добавлена в политику environment `github-pages`.
- 404 на `/v2/index.html` — файл лежал не в `web/` (`066dcf3f`).

Опровергнутые версии (не искать заново): блокировка расширением; проблема сети/404.
